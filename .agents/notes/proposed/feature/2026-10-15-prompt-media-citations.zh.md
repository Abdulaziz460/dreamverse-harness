# Agent Note: 提示词媒体引用

Status: proposed

[English](2026-10-15-prompt-media-citations.md) | 中文

## 问题

渲染调用接收一个 `prompt` 和一个单独的 `reference` 列表。提示词用 MiniMax H3 的标记指称每个参考，例如 `<Picture 1>`。这种设计有三个问题：

1. agent 要写两个输入，这两个输入可能不一致。
2. 这些标记只适用于一个模型。其他视频模型使用不同的写法。
3. 读提示词的人看不出每个标记指的是哪个媒体。

## 提案

提示词直接引用媒体。harness 从引用中读出发送列表。每个模型插件把引用换成它的模型的写法。现有的提示词和项目不需要迁移。

### 术语

- **引用**：提示词中指向一个项目条目的文字，写作 `@[<label>](dv:<kind>/<id>)`。
- **元素**：项目中一组有名字、有版本的参考媒体。元素是 harness 提供给人和 agent 的概念。视频模型不知道元素。
- **发送列表**：一次渲染发给模型插件的素材。
- **参考区**：版本编辑器中提示词旁边的媒体列表。
- **待用素材**：参考区中提示词没有引用的条目。

### 归属

| 步骤                             | 归属                                                     |
| -------------------------------- | -------------------------------------------------------- |
| 定义引用格式并解析引用           | `@dv/project`                                            |
| 在界面中插入和显示引用           | `@dv/ui-composer` 和 `@dv/ui-canvas`，遵循 `@dv/project` |
| 读出发送列表、展开元素、返回警告 | `@dv/shot-render`                                        |
| 声明参考上限，并转换引用写法     | 每个模型插件，例如 `@dv/fastvideo`                       |

`@dv/project` 负责引用格式，因为项目保存着引用所指的记录和历史。`@dv/models` 只是已注册模型的目录。

### 规则

1. 提示词可以引用一个素材、首帧，或一个元素的一个版本。
2. `shot.render` 没有 `reference` 参数。发送列表是被引用的素材，按首次引用的顺序排列。分镜计划的镜头使用同样的规则。
3. 参考区包含被引用的条目和待用素材。如果用户删除提示词引用的条目，那么界面拒绝删除，并高亮该条目的每个引用。如果用户删除一个引用，那么该条目留下，成为待用素材。
4. 如果参考区包含待用素材，那么 `shot.render` 不渲染，并返回警告。agent 或用户必须选择是否发送待用素材。
5. 首帧保存在 `continue_from` 字段中。如果提示词引用了首帧而该字段为空，那么 `shot.render` 返回错误。
6. 元素引用包含元素版本。渲染时，harness 把每个元素引用展开成该元素各个媒体的引用。agent 和模型插件不展开元素。
7. 每个版本保存原始提示词和展开后的提示词。`shot.render` 的结果包含展开后的提示词。
8. 每个模型插件声明参考数量的上限。如果展开后的提示词引用的参考超过上限，那么 `shot.render` 不渲染，并返回警告。

### 交付

- 每个 PR（Pull Request）只依赖已经合并的 PR。基础 PR 合并之后，再开下一个 PR。
- 每个 PR 在测试之外最多改动约 300 行。
- 每次合并之后，`main` 都能正常工作。

PR 按以下顺序提交：

1. 本 Agent Note。
2. `@dv/project` 中的引用解析器，以及 `@dv/fastvideo` 中到 `<Picture N>` 的转换。没有引用的提示词照常渲染。
3. `shot.render` 和分镜计划镜头从提示词读出发送列表，并更新工具描述和技能。
4. 版本编辑器和分镜计划视图中的引用缩略图。
5. 参考区和待用素材警告。
6. 首帧引用。
7. 元素引用及其展开。
8. 视频引用。
9. 音频引用。

## 考虑过的替代方案

**单独的参考列表。** 两个输入可能不一致。提示词是发送列表的唯一来源，可以避免这个错误。

**提示词中使用模型标记。** 每个视频模型的写法都不同。参考顺序变化时，按位置编号的标记也会改变编号。

**自动发送待用素材。** 这样做是替 agent 或用户做决定。harness 改为返回警告。

**警告后删除被引用的条目。** 删除后会留下没有目标的引用。

**只能引用元素中的单个媒体。** 用户每次都必须逐个选择媒体。为参考媒体分组的视频产品会为整组插入一个引用。

**由 agent 展开元素。** agent 必须查出每个元素的媒体，提示词也会丢失分组。

**由每个模型插件展开元素。** 每个插件都必须了解元素，而且每个插件都重复同样的代码。

**丢弃超过上限的媒体。** harness 会悄悄删掉媒体，替 agent 或用户做决定。

## 验收标准

1. `shot.render` 没有 `reference` 参数，发送列表来自提示词。
2. 对于引用一张图片的提示词，`@dv/fastvideo` 发送 `<Picture 1>` 和那张图片。
3. 有待用素材或参考数量超过模型上限的渲染会返回警告，并且不渲染。
4. 元素引用展开成该元素版本的媒体，版本同时保存两个提示词。

## 风险

1. agent 的工具约定会改变。使用 `<Picture N>` 标记的提示词在改动后不再起作用。
2. 展开后元素的文字由 harness 决定。模型对这段文字的理解，可能不如由它的插件写出的文字。
